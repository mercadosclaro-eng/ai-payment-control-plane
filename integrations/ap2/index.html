Varyntiq · independent demo

Settlement must be confirmed before a payment token is consumed.

This small, no-funds example addresses the failure reported in AP2 issue #308. It keeps reconciliation explicit: a failed provider call does not become a successful spend.

What the demo proves

ALLOWSettlement is attempted only after the policy decision.
FAIL SAFEAn unconfirmed settlement leaves the token available for retry.
BLOCKA denied decision never reaches the settlement provider.
NO REPLAYA confirmed token cannot be consumed twice.

Boundaries

This is an independent example, not an official AP2 integration. It uses no private keys, customer data, network calls or real funds. It does not claim that a payment succeeded until the settlement provider confirms it.
